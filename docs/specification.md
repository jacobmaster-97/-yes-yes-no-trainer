# Yes–Yes–No 棒球出棒判斷訓練程式｜Codex 開發規格

版本：V1.0（2026-11-09）  
文件用途：讓 Codex 依照本文件製作**可直接操作的互動訓練程式**，而不只是製作解說網頁或靜態簡報。  
語言：繁體中文（香港用字）

---

## 1. 專案背景與要解決的問題

使用者正在練習棒球打擊，平時能完成部分基本打擊動作，但在正式打席容易因為緊張、害怕三振、想等四壞球保送或思考過多技術細節，而錯失適合攻擊的來球。

要訓練的不是「每球都揮棒」，而是**每球都提前做好攻擊準備、看清來球，然後在適當時機決定出棒或放過**。程式須協助建立這個判斷及決策習慣，並記錄練習表現。

> 本工具是視覺判斷與決策模擬訓練，沒有追蹤真實球棒或身體動作的裝置，因此不能聲稱單靠按鍵便能量度真實擊球技術或實際打中棒球的機率。

## 2. Yes–Yes–No 的正確概念

1. **第一個 YES：準備好打** — 投手開始準備動作時，打者已建立平衡、視線對準投手，預備攻擊。
2. **第二個 YES：保持可以出棒的狀態** — 棒球出手後，持續追蹤球路，依然準備打，不要預先認定自己會放過這球。
3. **最後的判斷：GO / NO** — 在仍來得及揮棒的決策時間內，若球進入自己設定的可攻擊區域，選擇 **GO／出棒**；如球不值得攻擊，選擇 **NO／放過**。

**Yes–Yes–No** 代表「已準備打 → 繼續準備打 → 最後決定不打」。  
**Yes–Yes–Go** 代表「已準備打 → 繼續準備打 → 確認值得攻擊並果斷出棒」。

重要注意：
- 不要把 No 當成必須等到球抵達面前才作的臨時反應。決定要在合理的揮棒決策時間內完成。
- 不要把「全部好球」當成一律必須出棒；**好球帶（strike zone）**與**個人的可攻擊區（attack zone）**要分開設定。
- 在**兩好球**時，打者一般需要擴大保護範圍，V1 應有獨立可調的兩好球模式。
- 球接近身體時應優先考慮安全避球；模擬器不要以「不揮棒」懲罰明顯危險的觸身球。

## 3. V1 產品定位與技術限制

### 核心目標

開發一個**單一 HTML 檔案**（建議檔名 `yes-yes-no-trainer.html`），使用者可以在電腦直接雙擊開啟、離線操作，也可部署到 Vercel 等靜態網站平台，並可於 iPad 觸控操作。

### 技術要求

- 使用原生 HTML、CSS、JavaScript；**不依賴網絡、CDN、外部圖片、音效、字體或後端**，令本地離線可用。
- 建議使用 Canvas 2D 或 SVG 繪製投手、棒球飛行及好球帶。所有動畫元素與資料可程式化修改。
- 適配桌面、平板及手機，橫向畫面優先；支援全螢幕訓練。
- 繁體中文介面，文字大小足夠閱讀，支援觸控及鍵盤操作。
- 儲存使用者設定與最近的練習紀錄到 `localStorage`；提供 JSON 或 CSV 匯出及清除紀錄功能。
- 可在沒有任何上載素材的前提下，以內建向量圖示及簡潔插畫完成 V1。
- 不使用需要授權的球隊徽章圖片或第三方音樂。深藍、白底、橙／綠重點的教學插畫風格可作為視覺方向。

## 4. 使用流程（首頁至練習結束）

1. **首頁**：顯示「Yes–Yes–No 棒球出棒判斷訓練」，一句話說明玩法，選擇訓練模式。
2. **訓練設定**：設定每組球數、速度／難度、好球及壞球比例、是否兩好球模式、是否顯示好球帶、是否開啟即時教學提示。
3. **準備畫面**：呈現投手與打者視角的簡易球場；倒數 3、2、1 或按「開始下一球」。
4. **投球動畫**：畫面依序呈現預備、出手、來球前進，提供「YES」提示（新手教學模式），但不提前洩露該球的答案。
5. **作決定**：使用者按「GO／出棒」或「NO／放過」，亦可用鍵盤操作。
6. **即時回饋**：清楚顯示來球最終穿越好球帶的位置、原本可攻擊區、使用者選擇、建議選擇及原因。
7. **下一球**：可自動進入下一球，也可手動按下一球，避免回饋畫面太快消失。
8. **總結頁**：輸出判斷準確率、追打壞球次數、放過可攻擊好球次數、反應時間、進步建議與紀錄匯出。

## 5. 建議訓練模式

### 模式 A：慢速判斷教學（初學）

- 投球較慢；可在決策時點前提供較明顯的球路軌跡指示。
- 開啟第一個 YES、第二個 YES 的文字提示。
- 說明「GO／NO」的原因，尤其區分好球帶與適合攻擊區。
- 目的是學習規則與建立主動準備心態，而非測試極限反應時間。

### 模式 B：標準出棒決策（主要模式）

- 隨機混合可攻擊球、可放過球及靠近區域邊緣的球。
- 不顯示投球結果標籤；需依視覺軌跡自行判斷。
- 每組預設 **20球**，結束後提供分類統計與錯誤回顧。

### 模式 C：兩好球保護（進階）

- 擴大事先設定的保護區（protect zone），讓接近好球帶邊緣的來球也可能值得保護。
- 評分要根據此模式的預設規則；結果要註明「此為模擬訓練的判斷標準」，不是裁判判決。

### 模式 D：模擬打席（可列為 V1.1）

- 按棒球球數展示 Balls、Strikes（例如 0–0、1–2、3–1）。
- 根據模擬的好壞球結果和是否出棒推進球數。
- 必須嚴格區分「選擇出棒」與「實際擊中球」；V1 沒有揮棒追蹤器，**不可直接把按 GO 當成安打，也不可把按 GO 當成三振**。

## 6. 最重要的互動機制

### 畫面要素

- 投手簡化動畫、棒球向打者飛來的軌跡。
- 以打者視角（或易理解的示意視角）顯示本壘及一個好球帶矩形；可切換顯示／隱藏好球帶。
- 清晰標示畫面中「好球帶」及「可攻擊區／兩好球保護區」的差別（可在練習前設好，不應在正式判斷階段高亮答案）。
- 兩個主要大按鈕：**GO 出棒**、**NO 放過**。
- 鍵盤：`Space` 或 `J` = GO；`N` 或 `K` = NO；`Enter` = 下一球／開始（避免與 GO 衝突）。
- 每一球只接受一次有效選擇；投球未開始或結束後的多餘按鍵不應被記錄。
- 可暫停、重設本組；暫停時動畫及計時一併凍結。

### 動畫與時機

- 每球有四個明確狀態：`READY` → `WINDUP` → `BALL_IN_FLIGHT` → `FEEDBACK`。
- 在 `WINDUP` 顯示第一個 YES；`BALL_IN_FLIGHT` 的前段顯示第二個 YES（僅教學模式）。
- 設定一個**可調整的決策截止時點**，在球到達本壘前就關閉決策視窗。
- 超過截止時點仍未選擇，應記錄為「未及時決定」，不要自動當作 NO 或 GO。
- 接球與出棒的真實反應時間受速度、球路及打者能力影響；程式內的動畫時間只能當**可調的訓練參數**，不應宣稱是某年齡或某聯賽的真實生理標準。
- 不需要模擬完整真實物理引擎，但來球位置與飛行速度必須**在同一球內前後一致**，不得最後突然跳到與過程不符的位置。
- 可設「教學速度／標準速度／進階速度」及自訂動畫時間。預設數值是軟件體驗參數，不是官方投球速度。

## 7. 可攻擊區及題目生成規則

每一球資料建議包含：

```js
{
  id: 'p001',
  seed: 12345,
  endpoint: { x: 0.45, y: 0.55 }, // 標準化座標 0..1，代表球穿過本壘平面的位置
  pitchDurationMs: 1500,        // 可調的合成動畫時間，不代表現實投球時間
  isStrike: true,               // 是否位於模擬好球帶
  isAttackable: true,           // 是否位於本模式的可攻擊區
  isProtectable: true,          // 兩好球模式是否需要保護
  pitchVisualType: 'straight'   // V1 可先只有一致、可判斷的直線／小幅變化
}
```

- 設定一個固定、可視化的**模擬好球帶**。
- 另設定可調整、預設較窄的**可攻擊區（Attack Zone）**。
- 兩好球模式使用**保護區（Protect Zone）**，通常比一般可攻擊區稍大，邊界需可調。
- 隨機生成須涵蓋：好球帶中央、邊緣、明顯壞球及接近邊界的球，避免全部球都在中心。
- 同一個 seed 必須可重新產生相同的投球序列，方便重試與測試。
- 回饋必須顯示生成時採用的真實判定值；不能用使用者是否按 GO 反過來改變球路或答案。
- V1 暫不要求識別真實滑球、曲球及變速球；這些可列為未來版本。

## 8. 反應與評分規則

### 基礎判斷

| 模擬來球 | 選 GO | 選 NO |
|---|---|---|
| 落在可攻擊區 | 判斷正確（果斷攻擊） | 錯失可攻擊球 |
| 落在可攻擊區外 | 追打不理想的球 | 判斷正確（選擇放過） |
| 兩好球模式的保護區內 | 依兩好球模式規則給回饋 | 提示有被三振的風險（不直接判三振） |
| 明顯危險／觸身球 | 安全警示，不鼓勵硬打 | 安全放過／避球提示 |
| 在截止前未作選擇 | 未及時決定 | 未及時決定 |

### 需記錄的指標

1. 總投球數、有效作答數、未及時決定數。
2. **決策準確率** = 正確作出 GO/NO 判斷的投球數 ÷ 有效作答數。
3. **追打率** = 可攻擊區外按 GO 的次數 ÷ 可攻擊區外的有效作答球數。
4. **錯失攻擊機會率** = 可攻擊區內按 NO 的次數 ÷ 可攻擊區內的有效作答球數。
5. 反應時間（從「球出手」或明確統一的畫面事件開始計時；UI 必須註明起點）。
6. 按球區及訓練模式分組的表現，可在 V1.1 加入趨勢圖。

所有比率當分母為 0 時顯示「未有樣本」，不得顯示 NaN 或任意當作 0%。

### 回饋措辭例子

- 「正確：這球進入你的可攻擊區，果斷選擇出棒。」
- 「正確：這球在可攻擊區以外，選擇放過。」
- 「錯失機會：這球可攻擊，但你選擇了放過。」
- 「追打不理想來球：這球超出設定的攻擊區。」
- 「判斷太遲：下次更早追蹤出手位置與來球方向。」
- 「兩好球提醒：這球接近好球帶，需要考慮保護。」

回饋應**描述決策品質，不虛構安打、揮空、三振或實際身體動作**。

## 9. 畫面資訊架構與風格

### 畫面

1. `HomeScreen`：標題、簡短說明、模式選擇。
2. `SettingsScreen`：球數、速度、區域設定、是否兩好球、提示、音效開關。
3. `TrainingScreen`：投手、球路、好球帶、GO/NO 大按鈕、球數進度、暫停。
4. `FeedbackScreen`：本球答案、示意球路、原因、下一球。
5. `SummaryScreen`：指標、常見失誤、建議、重新開始、匯出紀錄。

### 視覺設計

- 白底、深藍色標題與圓角分框，藍色作主色，橙色表示判斷或移動，綠色表示正確，紅色表示錯誤。
- 使用清晰簡潔的 2D 卡通／向量人物風格（與使用者棒球訓練視覺筆記一致）。
- 如出現使用者角色，保留**深藍色元朗棒球隊衣、背面 Jerry 30、左手傳球及右手戴手套**的設定；**打擊慣用方向未知，請勿假設**，應提供可切換左打／右打視角，或 V1 使用不強調打擊慣用手的中性視角。
- 避免在訓練進行中用大量文字遮擋球路。
- 互動按鈕要適合 iPad 觸控，提供鍵盤焦點狀態及高對比度標示；不要只以紅綠顏色區分答案。

## 10. 本地資料與匯出

至少儲存：

```json
{
  "timestamp": "2026-11-09T00:00:00.000Z",
  "mode": "standard",
  "settings": { "count": 20, "difficulty": "beginner", "twoStrikes": false },
  "pitches": [
    { "id": "p001", "x": 0.45, "y": 0.55, "answer": "GO", "userChoice": "NO", "correct": false, "reactionMs": 650 }
  ]
}
```

- 可以在本機查閱最近的訓練紀錄。
- 提供 JSON 匯出供日後重分析，CSV 匯出供試算表使用。
- 不要求註冊、登入、雲端同步或上傳個人資料。

## 11. 非功能性要求與測試

- 開啟本地 HTML 後，在沒有網絡的情況下可運作。
- 反覆快速按鍵／觸控不會讓一球計分多次。
- 暫停、返回、重新開始不造成動畫狀態或計時錯亂。
- 在 iPad、桌面滑鼠及觸控環境下，兩個決策按鈕均清晰可用。
- 視窗縮放或旋轉後，不會造成好球帶座標與球路判定不一致。
- 測試 `GO`／`NO`／無回答、好球帶內外、保護區內外、決策截止、分母為 0 等情況。
- 提供 `?debug=1`（或設定中的開發測試開關），顯示每球最終座標及標準答案以驗證演算法；正式訓練預設關閉。
- 若使用 `file://` 環境，仍可完成訓練、儲存及下載紀錄（瀏覽器的本機儲存限制應有錯誤處理）。

## 12. V1 最低驗收標準（Definition of Done）

1. 有一個完整可開啟的 `yes-yes-no-trainer.html`。
2. 可以完成 20 球的標準模式，並選擇 GO／NO。
3. 每球有可辨識的投球動畫、完整的決策時間及合理回饋。
4. 可攻擊區與好球帶分開判定，兩好球模式可切換。
5. 球路、畫面及答案一致；即時回饋不提前洩題。
6. 可正確統計準確率、追打率、錯失攻擊機會率及逾時次數。
7. 可重開網頁查看本機紀錄，並可匯出 JSON／CSV。
8. 離線可用，無外部依賴，支援 iPad 觸控及桌面鍵盤。
9. README 說明開啟方式、按鍵、評分邏輯、已知限制及未來擴充方向。

## 13. 建議的 Codex 實作順序

1. 先完成頁面結構與回合狀態機（不要先做複雜動畫）。
2. 完成球路資料結構、攻擊區／好球帶判斷、種子亂數生成。
3. 完成 GO／NO、截止時點與不重複計分。
4. 完成投球動畫與可視化回饋。
5. 完成統計、localStorage、JSON／CSV 匯出。
6. 完成響應式版面、觸控、鍵盤、無障礙處理。
7. 自行執行測試案例，修復問題後交付單檔 HTML 和 README。

## 14. 明確不在 V1 範圍內

- 從攝影機分析真實揮棒姿勢或球棒速度。
- 預測真實投手球速、球種或職業打者反應能力。
- 真實安打、揮空、三振、四壞保送的全套物理模擬。
- 聯網對戰、帳號、雲端資料庫或排行榜。
